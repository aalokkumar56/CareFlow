# Backend clinical hazard register

Version: 2026-10-07. Requirement: REL-013 / BE-189. Status: Draft; clinical acceptance pending.

This register covers the prepared backend foundation, organization, local registration and existing outpatient source. It is not an exhaustive clinical risk assessment or permission to activate services. No accountable hospital clinical reviewer or accepted severity matrix is currently recorded. Every hazard below has unassigned clinical ownership and a pending residual-risk decision; no row is accepted by the implementation agent. Builds and transient source checks establish only the evidence stated in the linked tasks. Actual deployment, protected database exercises and clinical walkthroughs remain unexecuted.

## Review and release record

Before each affected release, record the exact source revision, migration/configuration versions and enabled workflows. Assign a named hospital clinical reviewer and technical owner to each applicable hazard, classify severity using the approved local matrix, record controls and synthetic exercise observations, and retain the review date and explicit residual-risk decision. The reviewer must identify newly discovered hazards; add new requirements to the master task register before creating layer-specific implementation tasks. Preserve older decisions and evidence when a control changes.

The clinical owner determines which unresolved hazards block activation under the approved matrix. Until that review exists, affected clinical activation remains blocked. The user's current test-file waiver does not establish database isolation, recovery, clinical correctness or release acceptance. Never attach patient data, credentials, raw payloads or live provider messages as review evidence.

## Acceptance evidence template

For each hazard retain: source/configuration revision; named technical owner and clinical reviewer; approved severity classification; exact synthetic workflow/preconditions; expected and observed outcomes; evidence reference/date; unresolved limitations; residual-risk decision/reason; affected services; next review trigger. An empty field is missing evidence. A green build cannot fill an unexecuted workflow result, protected restore or clinical decision.

This artifact requires no new clinical database table. Keep it under version control alongside affected deployment/control changes; record completed reviews in dated evidence files without replacing earlier decisions.
