# Dependency and container patch triage

Run `deploy/security/Scan-Dependencies.ps1` with an absolute protected `ReportDirectory` after dependency changes and before preparing a release. The operational script restores the API dependency graph, treats advisory-fetch failure as an error, inventories direct/transitive packages and captures official NuGet advisory findings. It creates a new timestamped report rather than overwriting prior evidence; findings fail the command. It does not execute tests, migrations, provider operations or upload clinical content. Reports contain package metadata and project paths; restrict access as deployment evidence.

The first source finding was System.Security.Cryptography.Xml 10.0.8: five high-severity NU1903 advisories in the actual API build. Only its direct reference was moved to 10.0.12, a stable same-major patch verified in the [official NuGet package listing](https://www.nuget.org/packages/System.Security.Cryptography.Xml/10.0.12). Record resolved transitive changes with the inventory; do not suppress NU1903 or infer that a clean dependency scan covers the OS/runtime/container image.

For each finding, the accountable owner must record advisory, affected deployed image/version, reachable feature, severity decision, patch deadline and residual-risk acceptance. Build a pinned replacement image and scan its OS/runtime/packages with the approved scanner; retain scanner/version/feed/time, immutable image digest and report. The repository's deployment templates require a reviewed immutable API image, but no container scan or owner has been invented here.

Exercise regression and rollback in the isolated accepted staging environment with synthetic inputs and no provider delivery. For data-changing releases, use BE-021's protected upgrade/recovery process: a code rollback never implies a destructive schema Down migration. Record application/schema compatibility, preserved history, the previously pinned image and forward-repair decision. The user has deferred unit/integration test files; required operational patch/rollback evidence remains pending.

Attach the captured vulnerable finding, patched dependency inventory/advisory scan, build, container report and regression/rollback results to BE-026. A restored patch and an advisory-free package report alone do not complete operator triage or release acceptance.
