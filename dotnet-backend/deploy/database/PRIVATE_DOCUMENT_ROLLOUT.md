# Private document storage rollout

Set `Storage:PrivateRoot` to an absolute shared durable volume outside the API content root (container example `/app/private-files/documents`). Restrict filesystem/volume credentials to the API/approved maintenance service; do not expose the directory with a web server/static mount. Back up both metadata and objects. New object keys are opaque tenant/version pairs; downloads verify the owning patient, tenant, recorded length and SHA-256, then stream through existing authorized controller endpoints.

Apply the reviewed additive metadata/version migration only in protected rehearsal first. Newly published bytes become visible only after version and document rows commit together. File or DB failure leaves retained staged/orphan objects; `PrivateDocumentReconciliationService.ReconcileTenantAsync` returns checksum/missing/abandoned/orphan evidence and never deletes them. Keep reconciliation manifests outside browser responses. Normal document deletion only soft-deletes metadata; immutable versions/objects are retained.

For legacy imports, invoke `PrivateDocumentMigrationService.MigrateTenantAsync` explicitly in each established tenant scope after backup. Persist its returned manifest and exception list to approved maintenance evidence. It retains document IDs, patients, visits, original filenames and originals; validates exact legacy patient paths; copies/hashes bytes, publishes immutable objects, locks current rows and updates only storage mappings transactionally. Repeat safely; already mapped rows are reported separately. Missing/mismatched mappings remain explicit unresolved exceptions. Original URLs are preserved in version provenance. Never run this automatically on startup or delete originals until approved reconciliation/restore proves every association and checksum.

No import, filesystem move, object deletion or live migration was executed while authoring this source. Shared-volume durability, access controls, backups, protected migration rehearsal and BE008 malware scan/quarantine acceptance remain release gates. Existing locally stored bytes remain available through tightly scoped authenticated legacy streaming until an approved import.
Storage checks existing file/directory ancestors for reparse points before creation and again afterward. Filesystem/volume ACLs must prevent untrusted modification between these checks; the managed provider does not promise a portable atomic no-follow filesystem primitive. Operator import must establish a named maintenance ServiceIdentity or authenticated operator in its tenant context so imported clinical mapping writes have durable audit evidence.
