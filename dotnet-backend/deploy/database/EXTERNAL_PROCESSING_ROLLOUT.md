# External processing approval activation

ExternalProcessing:Enabled defaults false. An API key, browser availability, user permission or generic hospital setting alone never approves dispatch. Existing Anthropic and Google clinical-note translation calls pass a server-defined provider/purpose gate before any network call. The gate requires authenticated scoped hospital person/service identity and latest unexpired allowed immutable policy revision with reviewer, approval reference and versioned consent/basis reference. No approval decision is seeded, inferred or exposed as a tenant-settings write API.

Provider/purpose keys are anthropic:conversation-draft, conversation-summary, message-classification, hospital-profile-extraction; google-translate:clinical-note-translation. Policy actor kind is person or service. Latest decision for a provider/purpose supersedes earlier decisions and can deny/revoke by appending Allowed=false. Runtime may read policies only, never create/rewrite/delete approvals. Migration preserves immutable decision history under forced tenant RLS. Approved basis and any patient-specific consent assessment must be established by accountable reviewers before activation; this source does not manufacture legal approval.

Approved dispatch and denied attempts record minimum protected technical audit referencing policy/revision/basis/source; prompt, notes, generated text, key and exceptions are omitted. Provider failure leaves original notes/messages usable and cannot sign generated text. Named model/client provider selection remains server-defined; no request-supplied endpoint/key is accepted.

AI input is bounded32Kcharacters, latest20 conversation messages only (2K each), draft12, summary20, and explicit patient-name prompt fields are omitted. Free text may still contain sensitive content; it is not claimed anonymized. Translation sends only the finalized versioned note body/language and does not mutate it. Google availability reflects approval plus configured server key. Anthropic client construction is lazy after approval; no key/network is needed for disabled behavior.

AddTenantProcessingPolicies and predecessor audit/session/role migrations require protected rehearsal before deploy. Provider contracts, country/purpose basis, reviewer authority and retention/consent decisions are unresolved operational inputs. No backend speech/transcription dispatch was found in source inventory; browser speech processing remains separately governed UI scope. No provider calls/test files/live migrations occurred.
