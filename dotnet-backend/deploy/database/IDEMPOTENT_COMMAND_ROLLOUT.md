# Opt-in durable command retry contract

`IIdempotentCommandExecutor` is source preparation for future typed HMS commands. No existing endpoint was opted in. The module must provide a stable server-defined namespace and typed business intent including every route target/association; never accept namespace/actor/tenant from HTTP fields. Canonical sorting and decimal normalization hash intent; raw intent/key/PHI are not stored. Scope is current authenticated hospital tenant, actor, namespace and SHA-256 key. A module must supply its approved finite retry/retention horizon, not a generic implicit policy; the foundation supports up to one year.

The supplied live-authorization callback runs before claiming and again before replay; it must validate the current server-side session, operator/role permissions, target/domain state using the provided transaction. Run all mutations, audit and optional outbox writes using that same session. The unique DB claim and transaction commit store only a minimum acknowledgement (resource ID, optional revision, bounded outcome) and status. Changed intent/in-flight work return 409; retry in-flight work after a short delay. An expired retry record returns 409 and cannot execute again under that key. A new key still requires domain/provider uniqueness beyond the retry horizon. No automatic purge is installed; retention/cleanup must preserve that approved horizon and domain evidence.

Deploy additive storage and restricted grants only after protected rehearsal. Concurrency/lost-response/rollback checks against deployed-equivalent roles and approved module retry policies remain release gates. These source changes have not applied migrations, changed existing commands or created tests/test files.
