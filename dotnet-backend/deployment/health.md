# Backend health and readiness

`GET /api/health` retains its liveness contract; `/api/health/live` also returns 200 without tenant resolution, authentication or dependency access. A live process may still be unable to serve clinical requests.

`GET /api/health/ready` checks all five runtime database authorities using read-only transactions, the shared role/grant boundary and SELECT 1. It checks that the configured private document root exists outside the API directory, has read access and contains no symlink/reparse ancestors. It never creates directories/files or reads application rows. Missing, insecure, unavailable or incorrectly privileged dependencies return 503 with only `{"status":"unready"}`; a successful probe returns `{"status":"ready"}`. Responses are no-store and nosniff. Probes run before tenant resolution; caller tenant headers do not affect them.

The response deadline is three seconds. A five-second process cache and one active readiness exercise bound anonymous probe traffic; detection/recovery can lag by this cache interval plus a probe. A blocked filesystem worker cannot hold the response past its deadline or accumulate additional workers. Runtime probes do not prove write permission, free capacity, schema compatibility, shared-volume durability or recovery; those remain deployment/storage acceptance checks.

The `CureFlow.Readiness` .NET Meter exposes `cureflow.readiness.checks` and `cureflow.readiness.duration` (milliseconds) with fixed dependency names and `ready`/`unready` outcome tags. It emits no tenant/patient identifiers, payloads, filenames, request paths, SQL or exception messages. Connect it through the approved metrics collector; no exporter, external alert delivery or operator identity has been invented. Command/outbox backlog and storage-capacity metrics require their feature contracts and reviewed operational scope.

Before acceptance, record the accountable operator and alert destination, probe cadence and outage threshold. In an isolated accepted environment, fail a dependency, verify readiness becomes 503 while liveness stays 200, verify one notification reaches that operator, restore the dependency and verify readiness and its alert recover. Check schema compatibility, writable private storage/capacity and role grants separately. A build and in-memory missing-service checks do not complete that operational exercise.
